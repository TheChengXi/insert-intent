# 需求文档：会话上下文模块地图注入（module-map-context）

## 项目意图
在每个新工作会话的第一个步骤开始时，将当前工作区 `.intentflow/_packages/` 顶层所有 `*.yml` 模块文件的**原文**拼接后，注入到会话上下文（作用类似 AGENTS.md）。模型无需扫描整个目录树即可获知各模块的职责、入口、依赖与分组文件地址，节省理解成本与 token。

**本次迭代（缺陷修复）**：`module-map-context` 已交付并装配到 web profile（入口 `index.js`、`lib/discover.js` / `lib/render.js` / `lib/inject-decision.js`）。因 DSH 宿主更新 + 调校其它上下文更新时反复重启 `dsh web`，暴露一个缺陷：插件"每会话至多注入一次"的判定是**进程内 `WeakSet`**（`inject-decision.js` 按 `agent.session` 键），进程一重启内存即清空，同一个会话恢复后被当成"未判定"再次注入——于是每次重启后同一对话里又多一份模块地图，形成反复注入。本次迭代把"每会话至多一次"的去重判定改为**跨进程重启/会话恢复仍成立的持久化判定**。

## 功能清单
1. 会话首步注入模块地图（每会话至多一次）
2. 去重判定持久化（宿主重启 / 会话恢复后不再重复注入）— **本次修复核心**
3. 工作区自适应（无 `_packages` 时优雅跳过；进程内持久，跨重启按官方降级重探）
4. yml 原文拼接（不解析 / 不加引导头 / 不刷新）

## 核心功能

### 核心功能1：会话首步注入模块地图（每会话至多一次，跨重启成立）
- **能力**：系统能够在每个新工作会话的首个符合条件的步骤（`agent/pre-step`）一次性读取 `.intentflow/_packages/` 顶层全部 `*.yml`，将拼接结果作为持久上下文快照注入该步骤批次末尾；同一会话**至多注入一次**，即使宿主进程重启、会话恢复或上下文被压缩也不再重复。
- **业务价值**：模型首轮即掌握模块地图，且同一对话全程只有一份快照，不因调试/重启宿主而污染上下文、不浪费 token。

### 核心功能2：工作区自适应（优雅跳过 + 进程内持久、跨重启降级重探）
- **能力**：系统能够判断当前工作区是否存在 `.intentflow/_packages/`；存在且含 `*.yml` 才注入，否则正常继续会话、不注入、不报错；进程内判定为跳过后续不补注；**跨宿主重启降级为重新探测** `_packages`（官方一致，DSH 不持久化跳过判定）。
- **业务价值**：同插件在无约定目录的工作区安全装配；进程内不因内容变化补注，跨重启照官方语义重探。

### 核心功能3：yml 原文拼接
- **能力**：系统能够将各模块 yml 文件内容**逐字逐行**拼接注入，不做内容改写、不做结构解析、不加额外引导头；会话中途即使内容变化也不刷新不替换。
- **业务价值**：注入内容与维护者在 yml 中写的一致；首步一帧定稿，避免会话内快照漂移。

## 业务规则

### 注入时机（每会话一次）
- **场景**：每个新工作会话的首个合格步骤。
- **行为**：首个符合条件的 `agent/pre-step` 进入非空批次时，读取 `_packages/*.yml` 并拼接为一个持久上下文快照，注入该批次末尾（位于直接用户消息、AGENTS.md 基线与运行时上下文之后）。
- **异常处理**：首步被拒绝或批次为空 → 基线留待本会话后续步骤首次进入时补入（同一会话只完成一次，不重复累积）。

### 去重判定（进程内 → 会话投影持久化）［本次修复核心］
- **场景**：会话进行中宿主进程重启 / 会话从持久存储恢复 / 上下文被压缩后继续。
- **行为**：插件注册一个**会话投影**（`ctx.sessionProjections`），在已提交（持久）事件上折叠，只认 `module-map-context` 来源的 `user/message`（`source.kind==='plugin' && source.plugin==='module-map-context'`）来置"已注入"标记；注入前用 `stateOf(session,key)` 读回，已注入则跳过。去重依据落在持久层而非进程内存，因此进程重启、恢复、压缩后都不会重注。保留进程内 `WeakSet` 作兜底（无投影装配或提交前间隔仍挡同进程重复）。
- **异常处理**：投影注册表不可用 → 降级为进程内 `WeakSet` 去重（同进程仍不重复；跨进程无法持久去重，属已知边界）。**官方一致做法，不引入自定义持久事件。**

### 注入位置（本次保持现状）
- **场景**：任何一次有效注入。
- **行为**：拼接结果处于本步骤注入序列**末尾**（位于直接用户消息、AGENTS.md 基线与运行时上下文之后，见既有决策 D3）。
- **异常处理**：无——位置固定。

### 扫描深度与内容
- **场景**：读取 `_packages` 目录时。
- **行为**：仅读 `.intentflow/_packages/` **顶层** `*.yml`，不递归子目录；按文件名排序拼接，每文件原文逐字保留（含缩进与注释）。
- **异常处理**：目录不存在 → 跳过；顶层无 `*.yml` → 跳过；个别文件读取失败 → 跳过该文件不阻塞其余；yml 语法不校验（原文拼接，不解析）。

### 会话中途刷新（不刷新）
- **场景**：`_packages/*.yml` 内容在会话中途被编辑，或会话恢复后内容有变。
- **行为**：不重新注入、不替换已有快照；保持首步已定的帧。
- **异常处理**：无——固定快照语义。

### 跳过判定（进程内永久，跨重启降级重探）
- **场景**：会话首步判定时 `_packages` 缺失或顶层无 `*.yml`。
- **行为**：本会话**进程内**判定为"已处理（跳过）"，后续步骤不再探测、不补注；**跨宿主重启后降级为重新探测** `_packages`——若目录/`*.yml` 出现则注入一次。原因：DSH 只接受内置持久事件类型，第三方无法安全持久化"已跳过"；官方插件从不持久化跳过判定，照官方语义降级。
- **异常处理**：无——按此规则：进程内不补，跨重启重探。

## 预设测试

> 从用户视角可执行的测试步骤，验证功能是否符合预期。

### 前置条件
- 工作区存在 `.intentflow/_packages/`，内含 ≥1 个 `*.yml`，内容符合给定模块格式。
- DSH 已装配 `module-map-context`。

### 测试步骤
1. **[启动新会话注入一次]**：在含 `_packages/*.yml` 的工作区启动新会话，发出第一条用户消息。
   **预期结果**：会话上下文末尾出现各模块 yml 的原文拼接（含每文件 packageName/summary/groups/files），顺序稳定，位于直接用户消息 / AGENTS.md / 运行时上下文之后。
2. **[重启宿主不重复]**：会话保持打开，**重启 `dsh web`**，回到同一会话继续操作。
   **预期结果**：模块地图**不重复注入**，上下文仍只有一份该快照（无叠加副本）。
3. **[恢复/压缩不重复]**：让会话被压缩或从持久存储恢复后继续操作。
   **预期结果**：模块地图不再重复注入；若被遮蔽，后续也不补入。
4. **[内容原样]**：对比注入文本与源 yml 文件内容。
   **预期结果**：逐字一致，无引导头、无改写。

### 异常场景
- **[无 `_packages` 目录]**：启动会话 → 进程内不注入、无报错；**跨重启重探 `_packages`**（官方一致：跳过不持久化）。
- **[`_packages` 为空]**：启动会话 → 进程内不注入，无报错。
- **[首步跳过、重启后有内容]**：首步无 `_packages` → 进程内跳过；**重启后重新探测** `_packages`，若出现则注入一次（与"永久跳过"的偏差，官方一致）。
- **[投影注册表不可用]**：`ctx.get('sessionProjections')` 不可用 → 降级为进程内 `WeakSet` 去重：同进程仍不重复；跨进程无法持久去重（已知边界，不引入自定义持久事件）。

## 边界收束

**此时必做**：
- 每会话至多注入一次，去重判定**跨宿主重启/会话恢复/压缩仍成立**——用**会话投影**（`ctx.sessionProjections`，折叠已提交持久事件）识别"已注入"，不依赖进程内存、不写自定义持久事件。
- 已注入识别依据：会话投影折叠出 `module-map-context` 来源的 `user/message`（`source.kind==='plugin' && source.plugin==='module-map-context'`）→ 标记"已注入"。
- 无 `_packages`/空目录进程内优雅跳过；跨重启重探 `_packages`（官方一致，跳过不持久化）。
- 保留进程内 `WeakSet` 兜底；保持注入位置在末尾、仅顶层 `*.yml`、文件名排序原文拼接、会话内不刷新。

**此时不做**：
- 会话中途刷新/增量更新 `_packages` 变更（L04）——用户明确"固定快照不刷新"，留待需要实时同步时。
- 递归扫描 `_packages` 子目录（L01）、顶层 yml 字节预算/截断（L02）、结构化注入（L03）——均为既有 later-on，不属本次修复范围。
- 跨重启持久化"已跳过"判定——DSH 只接受内置持久事件类型、官方插件不持久化跳过，故照官方降级为跨重启重探；如需"永久跳过"须回需求重定边界（不属本次）。

## 实现对齐

> 锚定现状：当前 `inject-decision.js` 用进程内 `WeakSet`（按 `agent.session`）做"每会话至多一次"，进程重启即失效。本次只在**去重判定**上做修复，注入的读取/渲染/位置逻辑不改。去重持久化照官方（`dsh-tmux-context`）用**会话投影**（`ctx.sessionProjections.register` + `stateOf`）识别"本会话是否已注入"，而非进程内存、也不写自定义持久事件。

- **[去重判定持久化（本次修复）]**：`apply` 装配时 `const projections = ctx.get('sessionProjections'); if (projections !== undefined) projections.register(createModuleMapProjection())` 注册会话投影；投影 `apply` 只在已提交持久事件的 `user/message` 且 `source.kind==='plugin' && source.plugin==='module-map-context'` 时置"已注入"。每次 pre-step 用 `isModuleMapInjected(projections, agent.session)`（即 `stateOf(session, 'moduleMapContext')===true`）探测：已注入 → 跳过。跨重启/恢复/压缩成立。保留进程内 `WeakSet`（`createInjectionDecider`）作兜底。
- **[跳过判定]**：首步无内容 → 进程内跳过（`WeakSet` 记住）；跨重启降级为重新探测 `_packages`（官方一致：不持久化跳过）。
- **[读取/渲染/位置]**：沿用现状 `lib/discover.js`（`ctx.fs` 读取、marker 定位项目根、仅顶层 `*.yml`、文件名排序）+ `lib/render.js`（原文拼接），注入位置保持 `[...decision.messages, snapshot]` 末尾。

**推导出的约束**（agent 基于环境推导、经确认/更新）：
- 去重判定必须**持久**，不依赖进程内存，跨重启/恢复成立。— ✅ 已确认（会话投影折叠已提交事件）
- 会话中途内容变更不刷新、快照固定。— ✅ 已确认
- 首步无 `_packages` → **进程内**永久跳过；跨重启降级重探（官方一致，原"跨重启持久"因 DSH 内置事件类型限制改为降级）。— ⏸ 已更新（官方降级，见 D-跳过）
- 投影注册表不可用 → 降级进程内 `WeakSet` 去重（同进程仍不重复）。— ✅ 已确认（推导）
- 已注入的识别按会话投影折叠的"本插件来源快照"，不按进程对象身份。— ✅ 已确认（推导）

**design 决策**（方案比较类，交由 design 阶段选择）：
- "已注入"的精确定位方式：按来源标识（`source.kind/plugin`）粗扫 vs 对注入文本做 digest 比对（`dsh-tmux-context` 用 digest 去重、内容变化才重注；本次用户选"固定不刷新"，故倾向来源标识粗扫免比对）。
- "已跳过"的持久载体：写一条持久 skip 标记（log-only 事件/消息）vs 持久保留一个"本会话已处理"判定并对重注场景做来源探测。需与既有会话持久事件模型兼容。
- 改造边界：重写 `inject-decision.js` 为"会话持久日志去重探测"，还是并入 `discover` 增加探测环节——保持现有 4 层拆分（装配/判定/渲染/发现）前提下最小改动。

## 与预设测试的关系
- 去重判定持久化 → 对应测试步骤 2（重启不重复）、3（恢复/压缩不重复）。
- 跳过判定持久 → 对应异常场景"无 `_packages` 目录"与"首步跳过、重启后有内容"。
- 首步注入位置/原文拼接/不刷新 → 对应测试步骤 1、4 及"会话中途不刷新"规则。
- 持久日志读取失败 fail-closed → 对应异常场景"持久日志读取失败"。
