# 后续想法备忘：module-map-context

> 设计阶段识别但**此时不做**的事项与未来可能演进方向。只记录想法，不做设计预留——需要时直接实现。

## 想法列表

- **L01：递归扫描 `_packages` 子目录**
  - 现状：用户明确仅顶层；现在 `discover` 只枚举该目录一层。
  - 何时做：当某工作区开始把模块 yml 放进嵌套子目录、顶层不再平铺时。
  - 备注：届时按"顶层 + 子目录统一排序"扩展 `discover` 的枚举逻辑即可。

- **L02：顶层 yml 总量字节预算 / 截断**
  - 现状：用户选"原文拼接、不截断"，当前无预算上限。
  - 何时做：当某工作区 `_packages/*.yml` 总量膨胀到足以冲垮每步上下文或明显拉高 token 时。
  - 备注：取舍是"原文完整" vs "控制注入体积"；若做，需决定丢弃/截断哪个文件及是否沿用 `agent-instructions` 式预算通报。

- **L03：结构化注入（解析 yml 后按模块/分组重排/加引导头）**
  - 现状：用户选"原文拼接、不解析、不加引导头"，实现保持逐字拼接。
  - 何时做：当模型需要"按模块分组、入口/依赖可索引"等高结构化表达，而原文不足以支撑时。
  - 备注：会引入解析依赖与渲染头，与当前"原文即语义"的取向冲突；届时按需新增。

- **L04：会话中途监听 yml 变更并增量更新**
  - 现状：用户明确"仅新会话首步一次"，不做运行时变更同步。
  - 何时做：项目在会话中被大量重构、模块地图频繁过期时。
  - 备注：会较大扩展插件生命周期（引入文件 touch 监听），现状不复用 `agent-instructions` 的动态 reconcile。

## 与当前设计的关系（轻量提示）

- L01/L02 只影响 `discover`/`renderConcat` 内部逻辑，当前接口无需提前预留，届时直接改内部即可。
- L03/L04 会改变注入消息的形态与来源生命周期，但当前采用一次性 snapshot 注入，未来改造时再整体抽象，不必现在做兼容接口。
